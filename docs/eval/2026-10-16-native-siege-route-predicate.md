# Avoid materializing water exclusions for land siege routes

The candidate used **8.24% less child CPU** by median paired comparison (8.21% pooled) on this fixed CI trace. All six registered CPU criteria and the separate compatibility requirements passed; the land siege route optimization is retained.

The land siege router previously enumerated every water tile into its exclusion set for each route request, then cloned the set into the search's visited set. The candidate checks the same stable exclusion predicate as positions are visited. It preserves the goal exception, unit and city-ring exclusions, first-step occupancy, territory entry, zone-of-control lock, neighbor and FIFO order, and the selected first step. The original set-based router remains byte-for-byte unchanged and still handles non-land siege routes. No new Game or AI state cache is introduced, and no strategy, rule, gene, global feature flag, source pin or verification policy changes.

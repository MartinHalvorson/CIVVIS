# Prospective Native trial: prewar Slinger preparation

Register sixteen future starts after shipping `capital-watch-arms-the-slinger`.
The observer qualifies the actual currently running unarmed capture-enabled
Native driver against the merged feature revision. Its frozen binary must
match the runtime and first decision receipts. The actual played genome must
retain `capital-walls-before-the-surprise` and omit the new bit. An empty,
disposable mirror capability probe must accept and read back the new bit;
no qualification order may enter the real game channel. Record installed
Lua bytes with loaded-byte identity explicitly unattested.

Acquire the existing screen path exclusively, without overwriting another
owner. The existing ladder deals ON/OFF from BLAKE2b of the original game tag,
gene, actual difficulty and victory lane. Keep the ladder's map, difficulty,
leader, victory conditions, production driver and other treatment choices.
The assignments are not selected for balance or replacements. Record all
actual commands, first-decision genomes, source revisions, binary hashes and
baseline treatment changes. The trial estimates no isolated effect if these
controls drift; every result remains in the record.

The first sixteen new attempt stems after activation form the cohort. A
continuation belongs to its original stem. Failed starts, unreadable arm
receipts and incomplete games remain assigned and are never replaced.
Persist each assignment before transient driver inspection. At the sixteenth
start remove only the unchanged lease file this observer created; preserve
any replaced or foreign file and record overruns. Do not stop or restart a
game. Outcome collection continues until all assigned starts are resolved;
report every unresolved run explicitly.

Primary observations are the assigned seat's actual Native terminal win/loss
and victory type. Report all sixteen separately, including difficulty, lane,
played arm and terminal source. Secondary observations are new-policy journal
entries, issued UPGRADE requests, subsequent host evidence of unit upgrades,
original-major-capital possession and own original-capital loss/return
markers. Command acceptance or a fresh adapter action is not host execution.
A changed unit ID requires corroborating host identity/upgrade events or a
clearly labeled inference; unresolved upgrades remain unresolved. Repeated
requests for one unit are not multiple upgrades. Rebuild city rosters for
every native state and classify original capitals by original-owner major
status, not current holder. A loss marker does not mean the city never returns.

This is a small, interleaved prospective mechanism/outcome trial. Keep raw
captures, failed observations, exact denominators and all source/genome drift.
Do not infer strength from score or survival alone, compare mismatched
historical cohorts as a causal effect, promote the default, or claim a
Domination victory without a verified actual terminal result.

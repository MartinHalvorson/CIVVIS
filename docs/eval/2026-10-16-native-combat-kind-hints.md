# Cache exact combat-kind hints for the Native reader

The candidate used **1.34% less child CPU** by the median paired comparison (1.37% pooled) on this fixed CI trace. Every registered acceptance criterion passed; the exact combat-kind predicate cache is retained.

The retained Native reader repeatedly checks whether old log lines could contain a combat event. Large state records carry unit `combat` fields, so the line index sends them to this predicate again on each request. The candidate memoizes only the exact existing `json_may_have_value` kind/combat boolean per immutable line range in the existing per-thread retained-log cache. A false result skips an observer call that would immediately return. A true result calls the unchanged observer, including its original prefilter, full JSON parser, root-kind check and ordered death accounting. No Game or AI state is cached.

The metadata follows the existing log-cache lifecycle. Validated append-only growth keeps results for its unchanged prefix; an existing full-read/path reset discards them. A retained older or arbitrary raw buffer uses the original uncached predicate. Existing file/tail validation rules and their limits are unchanged. Controls compare exact lexical outcomes for nested, duplicate, escaped, malformed and whitespace records; append, rewrite, shrink, partial tails, path switches and old buffers; and confirmed-death timing at selected state frames.

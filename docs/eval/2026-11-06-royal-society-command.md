# Royal Society contribution command bridge

The planner already chooses `Action::ContributeProject` and consumes the Builder in its reconstructed game. The native translator previously returned `None` for that action; the mod also had no `PROJECT_PRODUCTION` command dispatch. This change sends that existing intent to Civilization VI. It does not increase Royal Society's production valuation, create Builder jobs or change any gene, rules data, lane setting or default.

The native contract is shipped `DLC/Expansion2/Data/Expansion1_UnitCommands.xml:11`: `CommandType="UNITCOMMAND_PROJECT_PRODUCTION"`, with no interface mode. `Base/Assets/UI/Panels/UnitPanel.lua:2513` requests a no-mode command using `UnitManager.RequestCommand( pSelectedUnit, actionHash );`. The mod uses its existing strict command gate and that two-argument request; it never guesses a city-id parameter. The building's player-level modifier is `MODIFIER_PLAYER_ADJUST_UNIT_PROJECT_PERCENT` (`DLC/Expansion2/Data/Expansion1_Buildings.xml:318`), with amount2 at623. These are installed game files inspected on this host, not inferred rules.

Translation uses the observed native state, since the simulated Builder may already have been consumed. It requires mapped own actor and city, a charged Builder, a current project, and the actor on a completed, unpillaged district of that intended city. The emitted position guards the native request against stale movement. The native `CanStartCommand` gate remains responsible for actual building/project eligibility, charges and the once-per-city/turn limit. A refusal, unavailable command or raised request remains a refusal.

A successful request is labeled `project_contribution_requested`. It does not prove a production gain. The next-state accounting explicitly declares this verb unverifiable: the export has no per-command production attribution, and a Builder disappearing alone could also mean capture or death. Controlled host tests establish dispatch and rejection behavior; native execution still needs observation in an operator-approved game.

The motivating read-only Indonesia census covered20 completed ordinary lane runs following the operator handoff, excluding named studies and preparations. Nine had a recorded Royal Society build offer; none recorded the completed building. In `civvis-20261105T215700Z`, Lampung offered it at149/frame1 with a native9-turn quote while a Research Lab had5 turns remaining. Actual captured reads confirm that offer and the later unchanged availability. That is a production-policy research lead, not evidence this missing command caused those losses: these games did not build Royal Society. Its production-credit investigation remains separate from this command prerequisite.

Validation is tracked in the PR. Tests use actual translation and the actual shipped Lua dispatcher against a fake host; they do not launch Civilization VI, acquire a native game lock or change installed settings. No native game or lock waiter was launched or queued. No native strength or timing improvement is claimed.
